# Claude Env Switcher 设计说明

## 目标

构建一个轻量、原生的 macOS 菜单栏应用，帮助用户在不同 Claude 模型供应商的环境变量配置之间切换。

应用仅管理 `~/.claude/settings.json` 中的 `env` 字段。每次切换前必须完整备份原始文件；备份永久保留，由用户自行清理。

## 范围

### 包含

- 原生 SwiftUI 菜单栏应用，不显示 Dock 图标。
- 在应用内预置、添加、编辑、删除和排序供应商方案。
- 将每个方案保存为名称与完整 `env` 键值对。
- 一键将选中方案的 `env` 写入 `~/.claude/settings.json`。
- 切换前备份整个 `settings.json` 文件。
- 从当前 Claude 配置导入 `env` 为新方案。
- 打开备份目录与显示当前目标配置位置。

### 不包含

- 管理 `settings.json` 的非 `env` 字段。
- 自动清理或删除备份。
- 云同步、账户登录、跨平台支持或直接调用 Claude。
- 对供应商可用性、密钥有效性或网络连接的校验。

## 架构与数据

应用使用 SwiftUI 的 `MenuBarExtra` 提供菜单栏入口；“管理供应商”使用独立窗口。

应用方案数据保存在：

`~/Library/Application Support/Claude Env Switcher/providers.json`

每个方案包含稳定标识、显示名称和完整环境变量键值对。按照用户要求，包含 API Key 在内的值以明文保存在此本地文件中。应用应在首次保存前明确告知该行为。

备份目录为：

`~/Library/Application Support/Claude Env Switcher/backups/`

每次备份使用带毫秒级时间戳的唯一文件名，复制切换前完整的 `~/.claude/settings.json`。应用不限制数量、不自动删除，也不修改历史备份。

## 切换契约

给定用户选定的供应商方案，切换必须遵守以下不变量：

1. 目标是 `~/.claude/settings.json`。
2. 只有顶层 `env` 字段可被替换；其余 JSON 字段的语义必须保持不变。
3. 写入前必须成功完成完整备份。
4. 写入使用同目录临时文件加原子替换，避免中断造成半写入文件。
5. 写入后必须重新读取、解析并确认 `env` 与所选方案完全一致，才显示成功。
6. 任一步失败时不得继续下一步；失败提示必须标明读取、备份、写入或验证阶段。

当目标文件不存在时，应用提示用户创建该文件，不自动生成或覆盖。当目标文件不能解析为 JSON、无法访问或无法写入时，保持原文件不变。

## 交互

菜单栏显示当前已验证生效的供应商名称；初始无法识别时显示中性状态。

菜单提供：

- 已保存供应商列表与当前项标记，点击即可切换。
- 打开“管理供应商”。
- 打开备份目录。
- 在访达中显示 Claude 目标配置文件。

“管理供应商”窗口提供方案列表及名称、环境变量键和值的编辑表格，支持新增、编辑、删除和排序。新建方案时可从当前 `settings.json` 的 `env` 导入。删除仅作用于 `providers.json` 中的方案，不影响目标配置文件和任何备份。

## 错误呈现

每次失败以用户可理解的提示说明具体阶段与底层原因，例如文件不存在、JSON 格式无效、备份目录不可写、原子替换失败或写后校验不一致。失败提示不得显示完整 API Key 或完整环境变量值。

## 验收标准

- 可新增、编辑、删除、排序并重启后保留供应商方案。
- 切换前生成一个新的、完整的目标文件备份，且备份永久保留。
- 成功切换后目标文件的 `env` 与所选方案一致，非 `env` 字段保持一致。
- 目标文件不存在、无效 JSON、备份失败、写入失败或写后校验失败时，目标文件不会被应用覆盖。
- 菜单栏准确显示最近一次已验证成功的供应商。
- 应用不在错误提示、日志或普通界面中泄漏完整密钥值。

## 验证策略

单元测试覆盖方案持久化、JSON 局部更新、原子写入、唯一备份命名和错误分支。集成测试在专用临时目录创建带非 `env` 字段的样本配置，验证切换后的完整结构和备份内容。所有测试只使用专用临时路径，不触碰用户真实的 `~/.claude/settings.json`。

# 方案配置导出与导入

## 目标

把本机保存的全部供应商方案一次性带到另一台机器，不必逐个手工重建。

## 已定决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| API Key 是否随配置走 | 明文带上 | 与现有 `providers.json` 明文保存一致；导入后立即可用，无需补录 |
| 传输载体 | 文件与剪贴板都支持 | 文件适合换机整体搬迁，剪贴板适合即时发给自己 |
| 导入冲突 | 只追加，不覆盖 | 永不丢失本机已有数据 |
| 导出范围 | 全部方案 | 主场景是换机与多机同步，不需要挑选步骤 |
| 实现位置 | Rust 模块 + 薄命令层 | 打包/解析可纯函数单测；复用已有 `dialog` 依赖；ID 生成器在 Rust 侧 |

## 配置包格式

文件与剪贴板共用同一份 JSON 文本：

```json
{
  "kind": "cc-env-switcher-profiles",
  "version": 1,
  "profiles": [
    {
      "name": "DeepSeek V4",
      "env": {
        "ANTHROPIC_BASE_URL": "https://api.example.com/anthropic",
        "ANTHROPIC_AUTH_TOKEN": "sk-...",
        "ANTHROPIC_MODEL": "deepseek-v4-flash[1m]",
        "CLAUDE_CODE_EFFORT_LEVEL": "max"
      }
    }
  ]
}
```

三个顶层字段各有明确用途：

- `kind`：区分「选错了文件」与「配置包损坏」。缺少它时，任意 JSON 文件都能解析出空列表并报出无从判断的错误。
- `version`：唯一为将来预留的字段。格式若有变化，旧版应用读到新文件应明确要求升级，而不是静默导入残缺方案。当前唯一合法值为 `1`；大于 1 要求升级应用，缺失或非整数按损坏处理。
- `profiles`：每项仅含方案名称与环境变量。`env` 的值必须都是字符串，出现非字符串值按损坏处理。

### 配置包不含方案 ID

方案 ID 是切换、删除、判断「已生效」的认人依据。若导出时带上 ID，两台机器可能出现同一 ID，导致保存覆盖不相干方案、删除一次删掉两个、侧边栏生效标记认错对象。

因此配置包不含 ID，导入时在本机重新生成。这样「只追加不覆盖」不再是需要人记住的规则，而是结构上无法覆盖——包里没有 ID，就没有任何东西能指向已有方案。同一文件导入两次得到两份副本，符合追加语义。

## 导入合并规则

导入的方案一律追加到列表末尾，已有方案不作任何修改。

重名仅在真实撞名时加后缀：首次撞名为「X（导入）」，再撞为「X（导入 2）」，依次递增。同一批内部重名同样按此规则排开；不撞名则保持原名。

撞名判定的口径：名称按原样逐字符比较，不忽略大小写、不裁剪首尾空格——「x」与「X」视为不同名称，各自保留原名。判定的比较对象既包括本机已有方案，也包括同一批中已经处理过的方案，因此后缀在批内连续递增而不会重复。

空名称（或仅含空格）的方案照原样导入，不额外命名。这类方案在现有界面显示为「未命名方案」，导入不改变这一既有行为。

加后缀的理由：侧边栏只显示名称、地址与模型，三项全同时无法分辨哪个是新导入的，存在删错风险。后缀使列表重新可操作。

## 安全说明

配置包内 API Key 为明文。文件一旦离开本机（聊天、邮件、网盘、U 盘），保护它的不再是 macOS 账户权限，取得文件即取得全部 Key。

因此导出动作触发时先弹确认对话框陈述此事，而非仅写入 README——用户不会在导出前阅读 README。文件与剪贴板两条导出路径都要确认，剪贴板同样会把明文 Key 交给随后粘贴的任何位置。用户在确认框选择取消则中止导出，不产生文件、不写剪贴板。

README 的「数据位置」一节补一句说明导出文件含明文 Key，作为长期留存的提醒，与导出时的即时确认互补。

## 架构

新增 Rust 模块承担打包与解析，`main.rs` 增加四个薄命令。`providers.rs` 的 ID 生成函数由私有改为模块间可见，使导入时重新生成的 ID 与应用自身生成的格式一致，避免同一文件内出现两套 ID 风格。

### 纯函数（不接触文件系统）

| 函数 | 输入 → 输出 |
| --- | --- |
| 打包 | 方案列表 → JSON 文本 |
| 解析 | JSON 文本 → 方案列表，或一条中文错误 |
| 合并 | 已有列表 + 解析结果 → 新列表（重新生成 ID、按规则加重名后缀） |

纯函数使重名规则、`kind` 校验、ID 不重复均可直接单元测试，无需启动窗口或真实点击对话框。

### 命令层

四个命令：导出到文件、从文件导入、导出到剪贴板、从剪贴板导入。每个都是「调对话框或剪贴板 → 调纯函数 → 落盘」的薄壳。

导出到文件时保存对话框的默认文件名带日期（形如 `cc-env-switcher-profiles-20260808.json`），便于在换机时分辨多份导出。用户可自行改名。

导入的两个命令都返回「导入数量」与「加了后缀的数量」，供界面报数；导出命令无返回值。用户取消对话框与「导入 0 个方案」是两种不同结果，命令需能区分——前者不提示，后者提示配置包为空。

写入方案列表复用现有 `save_profiles`（先写临时文件再原子替换），导入中断不会留下半损坏的列表。

### 主线程死锁约束

`dialog` 插件文档明确要求阻塞式对话框不得在主线程调用，否则与事件循环死锁；Tauri 的规则是不带 `async` 的命令运行在主线程。两者相撞的表现是窗口无响应而非报错，属最难排查的一类故障。

因此凡弹出对话框的命令一律声明为 `async`。现有 `test_connection` 已是 `async` 命令，可循此先例。

### 新增依赖

`tauri-plugin-clipboard-manager = "2"`（Rust 侧 `ClipboardExt` 提供 `write_text` / `read_text`）。文件对话框无需新依赖，`dialog` 插件已在项目中。

## 界面

顶部工具栏与「查看备份」并排新增两个按钮：「导出全部方案」与「导入方案」。每个按钮点击后弹出小菜单选择文件或剪贴板。

放在顶部而非底部的理由：这两个操作作用于整个方案列表；底部一栏（删除方案／从当前配置导入／保存方案）作用对象均为选中的单个方案，混入会让人误解为只导出当前方案。

用小菜单而非并排四个按钮，是为在支持两种载体的同时控制工具栏复杂度。

## 错误处理

沿用现有提示条机制（`feedback.ts`：成功数秒后自动消失，失败可常驻）。

导入无法完成时分以下几种，每种说明「怎么办」而非只说「错了」：

| 情况 | 提示方向 |
| --- | --- |
| `kind` 不匹配 | 这不是导出的配置文件，请重新选择 |
| JSON 损坏 | 文件内容已损坏，建议重新导出一份 |
| `version` 高于应用支持 | 请先升级应用再导入 |
| 剪贴板内容非配置包 | 请先在旧机器上点导出到剪贴板 |
| 配置包合法但不含方案 | 这份配置里没有方案，请确认旧机器上已保存方案后重新导出 |

成功时报数：导入几个、其中几个因重名加了后缀。仅提示「导入成功」时用户无法判断是否有遗漏。

用户取消对话框不算失败，不作任何提示。

## 测试

Rust 单元测试（与现有模块一致）：

- 打包解析往返一致
- `kind` 不匹配报错
- 损坏 JSON 报错
- 版本过新报错
- 导入生成的 ID 与已有 ID 不重复
- 同一配置包导入两次得到两份而非覆盖——断言列表长度翻倍且原方案仍在
- 重名后缀按顺序排开
- 合法但方案列表为空的配置包可被识别，与损坏区分开
- 大小写不同的名称各自保留原名，不加后缀

其中「导入两次不覆盖」是核心保障。

对话框与剪贴板层不写自动化测试，需真实点击，改为手动验证并写入实现计划：导出到文件后在另一位置导入、导出到剪贴板后导入、故意选择无关 JSON 文件确认报错。

前端仅新增按钮与调用，无独立逻辑，不新增前端测试。
